# СППР REO (Robotics Economic Optimizer)
### Интеллектуальная система поддержки принятия решений по роботизации складских и производственных комплексов

---

## 1. Введение и назначение системы

### 1.1. Проблематика
Автоматизация интралогистики сопряжена с фундаментальным инвестиционным риском: рекламные характеристики роботизированных платформ (AMR/AGV) рассчитываются вендорами в идеальных условиях «чистого полигона». При переносе на реальный объект предприятие сталкивается с:
* геометрическими ограничениями проездов и тупиковыми зонами;
* простоями на перекрёстках и взаимными блокировками (deadlocks) флота;
* потерями времени на обязательные циклы зарядки тяговых батарей;
* искажением финансового срока окупаемости из-за неучтённых затрат на инфраструктуру, интеграцию и штрафов за срыв нормативов отгрузки (SLA).

Классическое предпроектное обследование силами внешних интеграторов занимает от 2 до 6 месяцев и требует значительных бюджетов до подтверждения базовой гипотезы о целесообразности проекта.

### 1.2. Решение REO
**СППР REO** — комплексный цифровой двойник, объединяющий параметрическое CAD-проектирование, микро-имитационное моделирование физики движения роботов и строгий инвестиционный анализ дисконтированных денежных потоков (DCF). 

Платформа даёт объективный ответ на ключевые вопросы топ-менеджмента:
1. *Сколько единиц техники реально потребуется для выполнения суточного грузопотока с учётом топологии конкретного здания?*
2. *Какая форма владения финансово выгоднее: капитальная закупка (CAPEX) или сервисная подписка (RaaS)?*
3. *Окупится ли проект при текущей стоимости капитала (WACC) и индексации фонда оплаты труда?*

### 1.3. Целевая аудитория
* **Технические директора (CTO) и главные инженеры:** верификация габаритных допусков, радиусов разворота, требований к полам (DIN 18202) и расчёт зарядной инфраструктуры.
* **Директора по логистике и цепям поставок (COO):** ликвидация узких мест топологии, контроль баланса входного и выходного буферов, гарантия выполнения плановой квоты.
* **Финансовые директора (CFO) и инвестиционные аналитики:** защита инвестиционного бюджета, анализ чувствительности (What-If), расчёт показателей NPV, IRR, DPP, TCO и оценка амортизационного щита.

## 3. Математический базис и кинематика

### 3.1. Предварительный подбор флота
Номинальный состав парка робототехнического комплекса рассчитывается исходя из целевой квоты грузопотока, коэффициента технической готовности тяговых аккумуляторов и геометрии складского маршрута.

Коэффициент готовности аккумулятора ($k_{\text{avail}}$):
$$k_{\text{avail}} = \frac{T_{\text{work}}}{T_{\text{work}} + \frac{T_{\text{charge}}}{60}}$$

где $T_{\text{work}}$ — время автономной работы робота под нагрузкой (ч), $T_{\text{charge}}$ — длительность быстрой зарядки до 95% (мин).

Расчётное время кругорейса полного цикла ($t_{\text{trip}}$) по топологическому графу:
$$t_{\text{trip}} = \frac{D_{\text{cycle}}}{v_{\text{max}} \cdot \eta_{\text{traffic}}} + \tau_{\text{манипуляций}}$$

где:
* $D_{\text{cycle}}$ — сумма средних кратчайших расстояний: $\text{Док приёмки} \to \text{Стеллаж} \to \text{Док отгрузки}$ (м);
* $v_{\text{max}}$ — максимальная паспортная скорость робота (м/с);
* $\eta_{\text{traffic}}$ — коэффициент снижения скорости из-за маневрирования на поворотах и разъездов ($\approx 0.85$–$0.92$);
* $\tau_{\text{манипуляций}}$ — технологическое время центрирования, захвата поддона и опускания гидравлической платформы ($70\text{ с}$).

Динамическая производительность одного робота ($Q_{\text{unit}}$):
$$Q_{\text{unit}} = \min\left(Q_{\text{passport}}, \frac{3600}{t_{\text{trip}}}\right) \cdot k_{\text{avail}}$$

Расчётный номинальный размер парка ($N_{\text{nominal}}$):
$$N_{\text{nominal}} = \left\lceil \frac{Q_{\text{target}}}{Q_{\text{unit}}} \right\rceil$$

Количество требуемых скоростных зарядных постов ($N_{\text{chargers}}$):
$$N_{\text{chargers}} = \max\left(1, \left\lceil N_{\text{nominal}} \cdot (1 - k_{\text{avail}}) \cdot 1.15 \right\rceil\right)$$

### 3.2. Навигация на базе Fast Marching Method (FMM)
В отличие от классических дискретных алгоритмов на графах (A*, RRT), непрерывное планирование траекторий внутри рабочих зон строится на численном решении уравнения Эйконала:
$$|\nabla T(x, y)| = \tau(x, y) = \frac{1}{v(x, y)}$$

Функция стоимости среды $v(x, y)$ непрерывно модифицируется факторами физического окружения:
* **Зона безопасности препятствий:** скорость плавно падает до нуля при приближении к стеллажам и колоннам ближе, чем на радиус безопасности $R_{\text{robot}} + 0.3\text{ м}$.
* **Качество напольного покрытия (DIN 18202):** полы с неровностями более 5 мм снижают скорость на 20%, суперплоские промышленные полы увеличивают скорость на 10%.
* **Масса перевозимого поддона:** нагрузка на пределе грузоподъёмности снижает динамику разгона на величину до 15%.

Робот совершает движение в направлении антиградиента поля времени:
$$\vec{v} = -v_{\text{max}} \cdot \frac{\nabla T}{|\nabla T|}$$
что исключает ломаные траектории и рывки при обходе статических препятствий.

### 3.3. Логика материального баланса склада (Конечный автомат FSM)
Симулятор реализует замкнутый двухсторонний материальный цикл:
1. `DOCK_INBOUND` (Приёмка): партии поступают по графику. Робот забирает паллету только при условии, что на стеллажах есть свободные ячейки ($N_{\text{current}} < C_{\text{capacity}}$). Если склад забит на 100%, приёмка блокируется.
2. `STORAGE_AISLE` (Адресное хранение): стеллаж обладает жёстко заданной вместимостью ячеек. Робот размещает груз, увеличивая счётчик занятости ячейки.
3. `DOCK_OUTBOUND` (Отгрузка): роботы второй технологической группы забирают накопленный груз со стеллажей и транспортируют его в зону выходных ворот.
4. **Фиксация доставки:** факт выполнения плановой квоты засчитывается **строго** в момент выгрузки поддона в воротах отгрузки.

## 4. Методология инвестиционного анализа (DCF)

Оценка эффективности вариантов автоматизации проводится по методике чистой приведённой стоимости на горизонте 5 лет с шагом расчёта в 1 год.

### 4.1. Базовый сценарий As-Is (Ручной труд)
* **Эквивалентный штат смены:** $\text{Workers}_{\text{shift}} = \lceil Q_{\text{target}} / 12 \rceil$ (норматив ручной комплектации — 12 палл/ч на оператора).
* **Списочный состав:** $\text{Staff}_{\text{manual}} = \lceil \text{Workers}_{\text{shift}} \cdot \text{Shifts} \cdot 1.15 \rceil$ (коэффициент замещения 1.15 учитывает плановые отпуска и больничные листы).
* **Фонд оплаты труда с начислениями (Loaded Salary):**
  $$\text{Salary}_{\text{loaded}} = \text{Salary}_{\text{gross}} \cdot 12 \cdot (1 + \text{Tax}_{\text{insurance}}[30.2\%]) \cdot (1 + \text{Overhead}_{\text{HR}}[10.0\%])$$
* **Годовые затраты As-Is:**
  $$\text{OPEX}_{\text{manual}} = \text{Staff}_{\text{manual}} \cdot \text{Salary}_{\text{loaded}} + \text{Staff}_{\text{manual}} \cdot 140\,000\text{ ₽ (амортизация, сервис АКБ и ТО электротележек/штабелёров)}$$

### 4.2. Сценарий CAPEX (Покупка в собственность)
* **Капитальные затраты проекта:**
  $$\text{CAPEX}_{\text{base}} = N_{\text{fleet}} \cdot C_{\text{robot}} + N_{\text{chargers}} \cdot 280\,000\text{ ₽} + 1\,200\,000\text{ ₽ (Сервер RMS/WMS)}$$
  $$\text{CAPEX}_{\text{gross}} = \text{CAPEX}_{\text{base}} \cdot (1 + K_{\text{integr}}[15\%]) \cdot (1 - \text{Discount}_{\text{WhatIf}})$$
  $$\text{CAPEX}_{\text{net}} = \text{CAPEX}_{\text{gross}} \cdot (1 - \text{Grant}_{\text{subsidy}})$$

* **Годовые эксплуатационные расходы (OPEX):**
  $$\text{OPEX}_{\text{robot}} = \text{OPEX}_{\text{supervisors}} + \text{OPEX}_{\text{energy}} + \text{OPEX}_{\text{maintenance}} + \text{SLA\_Penalty}$$
  где:
  * $\text{OPEX}_{\text{supervisors}}$ — оплата труда операторов RMS (1 специалист в смену с окладом $+25\%$ к ставке комплектовщика);
  * $\text{OPEX}_{\text{energy}}$ — расход электроэнергии на тягу и зарядку ($0.85\text{ кВт}$ на машину по тарифу $7.5\text{ ₽/кВт}\cdot\text{ч}$);
  * $\text{OPEX}_{\text{maintenance}}$ — регламентный сервисный контракт (SLA вендора) и серверная поддержка;
  * $\text{SLA\_Penalty}$ — штрафы за срыв квоты.

### 4.3. Сквозная штрафная модель (SLA Penalty Engine)
Если фактическая выработка флота по результатам имитационного моделирования оказывается ниже плановой квоты более чем на 10% ($Q_{\text{simulated}} < 0.9 \cdot Q_{\text{target}}$), проект штрафуется за нарушение логистических окон:
$$\text{Deficit}_{\text{hourly}} = \max(0, Q_{\text{target}} - Q_{\text{simulated}})$$
$$\text{SLA\_Penalty} = \text{Deficit}_{\text{hourly}} \cdot (\text{Shifts} \cdot 8 \cdot 250\text{ ч}) \cdot 1\,200\text{ ₽/палл}$$

Штраф напрямую увеличивает ежегодный OPEX роботизированного комплекса, предотвращая ложноположительные выводы об окупаемости неработающих конфигураций.

### 4.4. Сценарий RaaS (Роботизация как сервис)
* **Первоначальный CAPEX:** $0\text{ ₽}$.
* **Годовые затраты сервисной подписки:**
  $$\text{OPEX}_{\text{raas}} = N_{\text{fleet}} \cdot \text{Rate}_{\text{monthly}} \cdot 12 + \text{OPEX}_{\text{supervisors}} + \text{OPEX}_{\text{energy}} + \text{SLA\_Penalty}$$

### 4.5. Интегральные критерии окупаемости
Динамический чистый денежный поток года $t$:
$$\Delta\text{OPEX}_t = \text{OPEX}_{\text{manual}} \cdot (1 + i_{\text{fot}})^{t-1} - \text{OPEX}_{\text{robot}, t}$$
$$\text{TaxShield}_t = \frac{\text{CAPEX}_{\text{net}}}{5} \cdot 20\%\quad\text{(только для сценария CAPEX)}$$
$$CF_t = \Delta\text{OPEX}_t + \text{TaxShield}_t$$
$$\text{DCF}_t = \frac{CF_t}{(1 + \text{WACC})^t}$$

* **Чистая приведённая стоимость (NPV):**
  $$\text{NPV} = \sum_{t=1}^{5} \text{DCF}_t - \text{CAPEX}_{\text{net}}$$
* **Дисконтированный срок окупаемости (DPP):** определяется дробной интерполяцией момента перехода кумулятивного $\sum \text{DCF}$ через величину $\text{CAPEX}_{\text{net}}$.
* **Внутренняя норма доходности (IRR):** вычисляется решением уравнения $\text{NPV}(\text{IRR}) = 0$ итерационным методом Ньютона-Рафсона.
* **Индекс рентабельности инвестиций (PI):**
  $$\text{PI} = \frac{\text{NPV} + \text{CAPEX}_{\text{net}}}{\text{CAPEX}_{\text{net}}}$$

## 5. Руководство пользователя и сквозные сценарии

Интерфейс разделен на три взаимосвязанные рабочие зоны:
* **Зона 1 (Слева):** параметры объекта, сменность, макроэкономика (WACC, инфляция, субсидии) и выбор стратегии флота.
* **Зона 2 (Центр):** 2.5D/3D CAD-редактор планировки, расстановка оборудования и интерактивный плеер реплея симуляции.
* **Зона 3 (Справа):** сравнительная матрица 3 сценариев, детализация инвестиционной сметы, 5-летняя таблица DCF и ползунки анализа чувствительности What-If.

### Сценарий А. Экспресс-проверка типового склада (Верификация целесообразности)
1. Выберите в Зоне 1 отраслевой профиль **«Склад (Class A Warehouse)»**.
2. В Зоне 2 нажмите на верхней плашке кнопку **«Расписание»**: проверьте баланс партий. Если объём поставки ($100\text{ паллет}$) превышает вместимость стеллажа ($12\text{ паллет}$), кнопка «Применить» будет заблокирована. Задайте корректный объём партии ($10\text{ паллет}$).
3. В Блоке 6 (Зона 1, в самом низу) нажмите **«⚡ Рассчитать оптимальный флот»**. Система выполнит предрасчёт и выведет рекомендованную модель.
4. Нажмите **«Склад готов: Запустить расчёт и моделирование»**.
5. Наблюдайте 3D-симуляцию: робот забирает груз из зелёных ворот приёмки, отвозит на стеллаж, а затем доставляет на синюю рампу отгрузки.
6. В Зоне 3 разблокируется детальный отчёт: при малом грузопотоке система выдаст экономически обоснованное заключение `РЕКОМЕНДУЕТСЯ СОХРАНЕНИЕ AS-IS`, так как затраты на робототехнический комплекс ($4.81\text{ млн ₽}$) не окупаются итоговой операционной экономией: чистая дельта ($\Delta\text{OPEX}$) составляет всего 0.46 млн ₽/год из-за необходимости содержания сменных операторов RMS и инфраструктурных затрат (срок окупаемости >10 лет).

### Сценарий Б. Крупный распределительный центр (Высокая эффективность)
1. Разместите на плане несколько рядов стеллажей, увеличив ёмкость адресного хранения до $1000+\text{ паллет}$.
2. Задайте грузопоток $84\text{ палл/ч}$.
3. Нажмите расчёт флота: система подберёт парк из **8 машин** `Ronavi H1500`.
4. Запустите моделирование: роботы распределяют трафик без тупиковых коллизий, квота закрывается на $109\%$.
5. В Зоне 3 формируется инвестиционный вердикт `РЕКОМЕНДУЕТСЯ CAPEX-ПОКУПКА`: проект генерирует чистую годовую экономию $+20.46\text{ млн ₽}$, дисконтированный срок окупаемости составляет **1.5 года**, а чистый дисконтированный доход (NPV) превышает **50 млн ₽**.
6. Нажмите **«Печать в PDF»** в верхнем тулбаре для формирования готового двухстраничного меморандума для Инвестиционного комитета.

## 7. Развёртывание и запуск проекта

### 7.1. Запуск через Docker Compose (Рекомендуемый способ)
Требования: установленный Docker Engine 24+ и Docker Compose v2.

```bash
# Клонирование репозитория
git clone https://github.com/Ichimoku-123321/REO.git reo-decision-support-system
cd reo-decision-support-system

# Сборка и запуск изолированного контейнера с Nginx Alpine
docker-compose up -d --build

# Проверка статуса контейнера
docker-compose ps
```
После завершения сборки веб-интерфейс платформы доступен по адресу:  
**`http://localhost:3000`**

Остановка:
```bash
docker-compose down
```

### 7.2. Локальный запуск для разработки
Требования: Node.js 18.x или 20.x, менеджер пакетов npm 9+.

```bash
# Установка зависимостей проекта
npm install

# Запуск локального сервера разработки с поддержкой Hot Module Replacement (HMR)
npm run dev
```
Локальный сервер будет запущен по адресу: **`http://localhost:5173`**

### 7.3. Проверка типов и Production-сборка
```bash
# Строгая проверка типов компилятором TypeScript
npx tsc --noEmit

# Оптимизированная production-сборка бандла
npm run build
```

## 9. Ограничения текущей версии (MVP) и план развития

### Ограничения версии 1.0:
1. Моделирование перемещений выполняется в горизонтальной плоскости (2.5D/3D-кинематика) без физической анимации вертикального подъёма телескопических мачт высотных узкопроходных штабелёров.
2. В рамках экспресс-оценки моделируется одноуровневая геометрия объекта (без учёта грузовых межэтажных подъёмников).

### Дорожная карта развития (Roadmap):
* **Q4 2026:** поддержка открытого протокола **VDA 5050** для экспорта сгенерированных графов движения напрямую в промышленные диспетчерские системы (Fleet Management Systems).
* **Q1 2027:** модуль автоматической оптимизации топологии (Placement Optimizer) на основе генетических алгоритмов для поиска оптимальной расстановки стеллажей, минимизирующей пробег флота.
